To identify and fix the issue where each test file passes individually but fails when run together or when creating two carts or inventories in one program, follow these steps:

1. **Check for Global State in Tests:**
   Ensure that no tests are modifying global state that could affect other tests. This includes shared variables, databases, or any other resources that might be accessed by multiple tests.

2. **Isolate Test Environments:**
   Make sure each test runs in an isolated environment. This can be achieved by setting up and tearing down resources for each test. For example, if you are using a database, ensure that each test starts with a clean database and cleans up after itself.

3. **Review Shared Resources:**
   Check if there are any shared resources (like files, memory, or network connections) that might be causing the issue. Ensure that these resources are properly managed and isolated between tests.

4. **Debugging:**
   Add logging or debugging statements to identify where the shared state is being modified. This can help pinpoint the exact cause of the issue.

5. **Parallel Execution:**
   If you are running tests in parallel, ensure that the tests are designed to handle parallel execution. Sometimes, tests that are not designed for parallel execution can cause issues when run together.

6. **Test Suite Configuration:**
   Review the configuration of your test suite. Ensure that there are no settings that might be causing tests to share state unintentionally.

7. **Code Review:**
   Perform a code review to identify any potential issues in the code that might be causing the shared state issue. Look for any global variables, shared objects, or other resources that might be causing the issue.
